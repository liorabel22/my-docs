## A

### A

### Abstraction
Abstraction is the practice of hiding [implementation](/docs/c/keywords.mdx#implementation) details and exposing only the essential behavior of a concept.

### Algorithm
An algorithm is a step-by-step procedure for solving a problem or performing a task.

### Array
An array is a collection of elements stored in contiguous memory locations and accessed by index.

### Assembly
Assembly language is a low-level programming language that is closely related to machine code.

### Attribute
An attribute is a property or characteristic of a [variable](/docs/c/keywords.mdx#variable), [function](/docs/c/keywords.mdx#function), or [type](/docs/c/keywords.mdx#type) that provides additional information about its behavior or usage.

## B

### Binary
Binary is a base-2 numeral system that uses only two symbols: 0 and 1.

## C

### Compiler
A compiler is a program that translates [source code](/docs/c/keywords.mdx#source-code) written in a high-level programming language into machine code.

### Conditional Compilation
Conditional compilation is a feature of some programming languages that allows the [compiler](/docs/c/keywords.mdx#compiler) to include or exclude parts of the code based on certain conditions, typically using [preprocessor directives](/docs/c/keywords.mdx#directive).

### Constant
A constant is a [value](/docs/c/keywords.mdx#value) that cannot be changed during the execution of a program. In C, constants can be defined using the `const` keyword or by using [macros](/docs/c/keywords.mdx#macro) with the `#define` directive. Constants are often used to represent fixed values, such as mathematical constants (e.g., `PI`), configuration settings, or other values that should remain unchanged throughout the program. Using constants can improve code readability, maintainability, and help prevent accidental modification of important values.

## D

### Data Structure
A data structure is a way of organizing and storing data in a computer so that it can be accessed and modified efficiently. Common data structures include [arrays](/docs/c/keywords.mdx#array), [linked lists](/docs/c/keywords.mdx#linked-list), [stacks](/docs/c/keywords.mdx#stack), [queues](/docs/c/keywords.mdx#queue), [trees](/docs/c/keywords.mdx#tree), and [graphs](/docs/c/keywords.mdx#graph). Each data structure has its own strengths and weaknesses, and the choice of which data structure to use depends on the specific requirements of the program and the operations that need to be performed on the data.

### Declaration
A declaration is a statement that introduces a new [identifier](/docs/c/keywords.mdx#identifier) in a program, such as a [variable](/docs/c/keywords.mdx#variable), [function](/docs/c/keywords.mdx#function), or [type](/docs/c/keywords.mdx#type). Declarations specify the name and type of the [identifier](/docs/c/keywords.mdx#identifier), and may also include an initial [value](/docs/c/keywords.mdx#value) or other [attributes](/docs/c/keywords.mdx#attribute). Declarations are typically placed at the beginning of a [source file](/docs/c/keywords.mdx#source-code) or within a [function](/docs/c/keywords.mdx#function) to define the [scope](/docs/c/keywords.mdx#scope) and lifetime of the [identifier](/docs/c/keywords.mdx#identifier).

### Directive
A directive is a special instruction that is processed by the [preprocessor](/docs/c/keywords.mdx#preprocessor) before the code is compiled. Directives are typically used to include [header files](/docs/c/keywords.mdx#header-file), define [macros](/docs/c/keywords.mdx#macro), and control [conditional compilation](/docs/c/keywords.mdx#conditional-compilation).

## E

### Edge
An edge is a connection between two [vertices](/docs/c/keywords.mdx#vertex) in a [graph](/docs/c/keywords.mdx#graph) data structure.

### Enumeration
An enumeration is a user-defined data type that consists of named integer constants.

### Executable Program
An executable program is a file that can be run by the operating system to perform a specific task.

## F

### Function
A function is a reusable block of code that performs a specific task and can be called from elsewhere in a program.

### Function Call
A function call is an expression that invokes a [function](/docs/c/keywords.mdx#function) and passes control to it, optionally providing [arguments](/docs/c/keywords.mdx#argument) that the function can use to perform its task. When a function is called, the program execution jumps to the function's code, executes it, and then returns to the point where the function was called, optionally returning a [value](/docs/c/keywords.mdx#value) if the function is designed to do so. Function calls are a fundamental aspect of programming, allowing for code reuse, modularity, and abstraction, as they enable programmers to break down complex problems into smaller, manageable pieces of code that can be developed and tested independently.

## G

### Graph
A graph is a data structure made up of [vertices](/docs/c/keywords.mdx#vertex) connected by [edges](/docs/c/keywords.mdx#edge).

## H

### Header File
A header file is a file that contains [declarations](/docs/c/keywords.mdx#declaration) of [functions](/docs/c/keywords.mdx#function), [variables](/docs/c/keywords.mdx#variable), and other [identifiers](/docs/c/keywords.mdx#identifier) that can be shared between multiple [source files](/docs/c/keywords.mdx#source-code). Header files typically have a `.h` extension and are included in [source files](/docs/c/keywords.mdx#source-code) using the `#include` [directive](/docs/c/keywords.mdx#directive).

## I

### Identifier
An identifier is a name used to identify a [variable](/docs/c/keywords.mdx#variable), [function](/docs/c/keywords.mdx#function), [type](/docs/c/keywords.mdx#type), or other [declaration](/docs/c/keywords.mdx#declaration) in a program. Identifiers must follow certain rules, such as starting with a letter or underscore, and can contain letters, digits, and underscores. Identifiers are case-sensitive, meaning that `myVariable` and `myvariable` would be considered different identifiers.

### Implementation
Implementation refers to the actual code that defines how a [function](/docs/c/keywords.mdx#function), [data structure](/docs/c/keywords.mdx#data-structure), or [algorithm](/docs/c/keywords.mdx#algorithm) works. It is the concrete realization of an abstract concept or specification, and it can vary depending on the programming language, platform, or design choices made by the programmer. Implementation details are often hidden from the user through [abstraction](/docs/c/keywords.mdx#abstraction), allowing them to interact with the functionality without needing to understand the underlying code.

### Inline Function
An inline function is a [function](/docs/c/keywords.mdx#function) that is expanded in place where it is called, rather than being invoked through a traditional [function call](/docs/c/keywords.mdx#function-call). This can improve performance by eliminating the [overhead](/docs/c/keywords.mdx#overhead) of a function call, especially for small, frequently called functions.

### Interpreter
An interpreter is a program that directly executes instructions written in a programming or scripting language without requiring them to have been compiled into machine code.

## L

### Linked List
A linked list is a linear data structure where each element points to the next one.

### Linker
A linker is a program that combines one or more [object files](/docs/c/keywords.mdx#object-file) generated by a [compiler](/docs/c/keywords.mdx#compiler) into a single [executable program](/docs/c/keywords.mdx#executable-program). The linker resolves references between the object files, such as function calls and variable accesses, and ensures that all necessary code and data are included in the final executable. It may also link against external libraries, allowing the program to use precompiled code provided by the library. The linking process can be static or dynamic, depending on whether the libraries are included in the executable or loaded at runtime.

## M

### Macro
A macro is a [preprocessor directive](/docs/c/keywords.mdx#directive) that defines a name for a code fragment, which can be substituted in the [source code](/docs/c/keywords.mdx#source-code) before compilation. Macros can be used to define [constants](/docs/c/keywords.mdx#constant), create [inline functions](/docs/c/keywords.mdx#inline-function), or simplify complex code patterns. They are defined using the `#define` directive and can take parameters, allowing for more flexible and reusable code. However, excessive use of macros can lead to code that is difficult to read and maintain, so they should be used judiciously.

## O

### Object File
An object file is a file generated by a [compiler](/docs/c/keywords.mdx#compiler) that contains machine code and other information needed to create an [executable program](/docs/c/keywords.mdx#executable-program). Object files typically have a `.o` or `.obj` extension and are not directly executable. They may contain code, data, and metadata, such as symbol tables and relocation information, which the [linker](/docs/c/keywords.mdx#linker) uses to combine multiple object files into a single executable. Object files can also be used to create libraries, which can be linked into other programs to provide reusable functionality.

### Overhead
Overhead refers to the additional time, memory, or resources required to perform a task beyond the essential operations. In programming, overhead can be associated with function calls, memory allocation, or other operations that introduce extra processing or resource usage. Reducing overhead is often a goal in optimizing code for performance, as it can lead to faster execution times and more efficient use of system resources.

## P

### Preprocessor
A preprocessor is a program that processes [source code](/docs/c/keywords.mdx#source-code) before it is compiled. It can perform tasks such as macro substitution, file inclusion, and [conditional compilation](/docs/c/keywords.mdx#conditional-compilation).

## Q

### Queue
A queue is a linear data structure that follows the FIFO principle.

## R

## S

### Scope
Scope refers to the region of a program where a [variable](/docs/c/keywords.mdx#variable), [function](/docs/c/keywords.mdx#function), or [type](/docs/c/keywords.mdx#type) is accessible and can be used. In C, there are different types of scope, including global scope, local scope, and block scope. Global scope refers to identifiers that are accessible throughout the entire program, while local scope refers to identifiers that are accessible only within a specific [function](/docs/c/keywords.mdx#function) or block of code. Block scope is limited to the block in which the identifier is declared, such as within a loop or conditional statement. Understanding scope is important for managing variable lifetimes, avoiding naming conflicts, and ensuring that the correct values are used in different parts of a program.

### Source Code
A source file is a file that contains code written in a programming language, which can be compiled or interpreted to create an [executable program](/docs/c/keywords.mdx#executable-program).

### Stack
A stack is a linear data structure that follows the LIFO principle.

### Statement
A statement is a single line of code that performs a specific action in a program. In C, statements are typically terminated with a semicolon (`;`), which indicates the end of the statement. Statements can include variable declarations, function calls, control flow statements (like `if` or `for`), and other expressions that perform operations or manipulate data.

### Structure
A structure is a user-defined [data type](/docs/c/keywords.mdx#type) in C that allows the grouping of different types of variables under a single name. Structures are defined using the `struct` keyword and can contain variables of various [data types](/docs/c/keywords.mdx#type), including other structures. This allows for the creation of complex [data structures](/docs/c/keywords.mdx#data-structure) that can represent real-world entities and their attributes in a more organized manner.

## T

### Tree
A tree is a hierarchical data structure composed of nodes connected by edges.

### Type
A type is a classification of data that defines the kind of values a variable can hold and the operations that can be performed on those values. In C, common data types include `int` for integers, `float` for floating-point numbers, `char` for characters, and `void` for functions that do not return a value. Types can also be user-defined, such as [structures](/docs/c/keywords.mdx#structure) and [enumerations](/docs/c/keywords.mdx#enumeration), allowing programmers to create complex [data structures](/docs/c/keywords.mdx#data-structure) and [abstractions](/docs/c/keywords.mdx#abstraction).

## V

### Value
A value is a specific piece of data that can be assigned to a [variable](/docs/c/keywords.mdx#variable) or used in an [expression](/docs/c/keywords.mdx#expression). Values can be of various [data types](/docs/c/keywords.mdx#type), such as integers, floating-point numbers, characters, or strings. In C, values can be literals (e.g., `42`, `'A'`, `3.14`) or the result of expressions and computations. The value of a variable can change during the execution of a program, depending on the operations performed on it.

### Variable
A variable is a named storage location in a program that can hold a value of a specific [data type](/docs/c/keywords.mdx#type). Variables can be used to store and manipulate data during the execution of a program. Each variable has a unique identifier (name) and can be assigned a value, which can be changed throughout the program's execution. Variables must be declared before they can be used, specifying their [data type](/docs/c/keywords.mdx#type) and optionally an initial value.

### Vertex
A vertex is a fundamental unit in a [graph](/docs/c/keywords.mdx#graph) data structure, representing a point or node that can be connected to other vertices by [edges](/docs/c/keywords.mdx#edge). Vertices can hold data and are used to model relationships and connections in various applications, such as social networks, transportation systems, and computer networks.
